# 自動運転シミュレータ 制御仕様書

自動運転シミュレータの**運転制御に関する技術仕様**をまとめた文書です。

- **人が読む場合**：制御の設計に必要な入出力・物理挙動・コース・計測指標の正確な仕様を確認できます。
- **生成AIに読み込ませる場合**：この文書1つでシステム全体の前提を伝えられるように書かれています。
  「この仕様書に従って `controllers/your_controller.py` の `control(obs)` を改良して」のように依頼してください。

> はじめて参加する人向けの導入・環境構築・上達のステップは [参加者ガイド.md](参加者ガイド.md) を参照。

---

## 1. システム概要

見下ろし型2Dコースを走る自動運転制御を作るシミュレータです。
物理・描画・コース・計測はエンジン側で固定されており、**参加者が書くのは運転制御ロジックだけ**です。

### 1.1 構成モジュール

```
intern/
├─ main.py                    # 起動・2分割同時走行・結果出力
├─ config.py                  # 全定数（物理・画面・計測・センサー）※本書の数値の出典
├─ engine/                    # エンジン（参加者は編集しない）
│   ├─ types.py               #   Car / Action / sanitize_action
│   ├─ physics.py             #   車両運動モデル（前輪操舵＋グリップ限界＋路面効果）
│   ├─ track.py               #   コース読込・走行可否・路面種別
│   ├─ sensors.py             #   Observation 生成（レイキャスト等）
│   ├─ runner.py              #   参加者コードの安全実行（例外・出力を隔離）
│   ├─ simulator.py           #   1台分の走行進行（CP通過・衝突・タイム集計）
│   └─ evaluator.py           #   フィードバック指標の算出
├─ render/view.py             # 描画
├─ courses/course_01/         # コースデータ（mask.png + meta.json）※本番コースは当日追加配布
└─ controllers/
    ├─ interface.py           # Observation / Action の定義と補助関数
    ├─ sample_controller.py   # 配布時の基準（編集せず比較用に残す）
    └─ your_controller.py     # ★参加者が編集するファイル
```

- 依存の向き：`main → engine/render → controllers`。
- 制御はエンジン内部を知らず、毎フレーム渡される `Observation` を見て `Action` を返すだけです。

### 1.2 実行ループ

1. エンジンが現在の車両状態から `Observation` を生成する。
2. 参加者の `control(obs)` が呼ばれ、`Action` を返す。
3. エンジンが物理モデルで車を1ステップ進め、衝突・CP通過・タイムを判定する。
4. 上記を **固定タイムステップ 1/60 秒**（60 FPS）で繰り返す。PC性能に結果は依存しない。

### 1.3 実行方法

```bash
# 左ビュー=第1引数, 右ビュー=第2引数 の制御で同時走行
python main.py sample_controller your_controller --course course_01
```

- 制御名は `controllers/` 内のモジュール名（`.py` を除いたファイル名）。
- ファイルを好きな名前でコピーすればその名前の制御として走らせられる（比較用）。
- オプション：`--course コース名`、`--fast`（描画ペーシング省略）、`--max-frames N`（打ち切り）。

## 2. 座標系・単位系

| 項目 | 定義 |
|------|------|
| 距離 | ピクセル [px] |
| 時間 | 秒 [s]。1フレーム = `dt` = 1/60 s（固定） |
| 角度 | ラジアン [rad] |
| 原点 | 画面左上。x は右向きが正、**y は下向きが正** |
| 向き `heading` | +x 方向 = 0。y が下向きのため**時計回りが正** |
| 相対方位 | `bearing_to()` の返り値は **正=右前方 / 0=正面 / 負=左前方** |

## 3. 制御インターフェース

### 3.1 control() の契約

参加者は `controllers/your_controller.py` に次の関数を1つ定義します：

```python
from controllers.interface import Action, Observation, bearing_to, distance_to

def control(obs: Observation) -> Action:
    ...
    return Action(steer=..., accel=..., brake=...)
```

- 毎フレーム（60回/秒）呼ばれる。**重い計算を書くと実時間の走行に影響する**ため禁止。
- 返り値は `Action`。それ以外の型を返すと、そのフレームは `Action(0,0,0)`（何もしない）扱い。

### 3.2 入力：Observation（frozen dataclass）

| フィールド | 型 | 意味 |
|-----------|----|------|
| `speed` | float | 現在の速さ [px/s]（0 〜 最高速度 420） |
| `pos` | (float, float) | 自車の絶対座標 (x, y) [px] |
| `heading` | float | 自車の向き [rad]（第2章の座標系に従う） |
| `next_cp` | (float, float) | **次に通るチェックポイント**の絶対座標。通過するたび次の1個へ更新。最後のCP＝ゴール |
| `rays` | dict[str, float] | 各方向の壁までの距離 [px]（第6章） |
| `surface` | str | いま踏んでいる路面：`'road'` / `'ice'` / `'mud'` / `'boost'`（第5章） |
| `progress` | float | 進捗 0.0〜1.0（規定周回分を含む全体進捗。参考・デバッグ用） |
| `dt` | float | このフレームの時間 [s]（= 1/60） |

**重要な設計思想（カーナビ型）**：中心線をなぞる「答え」は渡されません。
`next_cp` は目的地を示すだけで、**連続するCPの直線上には必ず壁（コースの曲線）があります**。
壁センサー `rays` で「道なり」に走りながら `next_cp` の方向へ向かうのが基本形です。

### 3.3 補助関数（controllers/interface.py）

```python
bearing_to(obs, point)   # point=(x,y) の相対方位 [rad]。正=右, 負=左, 0=正面
distance_to(obs, point)  # point までの直線距離 [px]
```

### 3.4 出力：Action（frozen dataclass）

| フィールド | 範囲 | 意味 |
|-----------|------|------|
| `steer` | -1.0 〜 1.0 | ステアリング。**負=左, 正=右**。前輪切れ角 = `steer × 0.60` [rad] |
| `accel` | 0.0 〜 1.0 | アクセル開度 |
| `brake` | 0.0 〜 1.0 | ブレーキ踏力 |

- `accel` と `brake` を同時に出すことは可能（駆動と制動が打ち消し合う）。

### 3.5 異常時の扱い（安全装置）

| ケース | エンジンの挙動 |
|--------|----------------|
| 範囲外の値 / NaN / None / 数値以外 | 自動補正（クランプまたは 0.0 に置換）。車は壊れない |
| `control()` が例外を送出 | そのフレームは `Action(0,0,0)`（惰性走行）。例外回数は記録され結果に表示される |
| 返り値が `Action` 以外 | 同上（`Action(0,0,0)` 扱い＋記録） |

### 3.6 状態の保持

`control()` は関数1つですが、モジュールのグローバル変数に前フレームの情報などを保持できます
（例：スタック検出用のタイマー）。ただし**同じ制御名を左右両方に指定すると状態が共有される**点に注意。

## 4. 車両物理モデル

前輪操舵のキネマティック車両モデル＋グリップ限界。毎フレーム以下の順で計算されます
（実装：`engine/physics.py`）。`surf` は足元の路面効果（第5章）。

### 4.1 縦方向（加速・制動・抵抗）

```
drive   = accel × 260 × surf.accel + surf.boost     # 駆動 [px/s²]
braking = brake × 520 × surf.brake                  # 制動 [px/s²]
drag    = 0.8 × surf.drag × v                       # 速度比例の抵抗 [px/s²]
v_next  = clamp(v + (drive − braking − drag) × dt,  0,  420 × surf.vmax)
```

### 4.2 操舵（前輪切れ角 → 回頭）

```
delta    = steer × 0.60                             # 前輪切れ角 [rad]
yaw_rate = (v / 32) × tan(delta)                    # 回頭角速度 [rad/s]（32=ホイールベース）
```

速度が 0 だと回頭できない（＝止まったままハンドルを切っても向きは変わらない）。

### 4.3 グリップ限界（滑り）

必要な向心加速度が限界を超えると、曲がりきれずに滑ります：

```
a_lat = v × yaw_rate                                # 要求向心加速度 [px/s²]
if |a_lat| > 900 × surf.grip:
    yaw_rate ×= (900 × surf.grip) / |a_lat|         # 回頭が制限され外へ膨らむ
    v ×= 0.98                                       # わずかに減速（スクラブ）
```

### 4.4 位置・向きの更新

```
theta_next = normalize(theta + yaw_rate × dt)       # -π〜π に正規化
x_next     = x + v × cos(theta) × dt
y_next     = y + v × sin(theta) × dt
```

### 4.5 物理定数一覧（config.py）

| 定数 | 値 | 意味 |
|------|-----|------|
| `DT` | 1/60 s | 固定タイムステップ |
| `V_MAX` | 420 px/s | 最高速度 |
| `ENGINE_ACCEL` | 260 px/s² | アクセル全開時の駆動加速度 |
| `BRAKE_DECEL` | 520 px/s² | ブレーキ全開時の制動減速度 |
| `DRAG` | 0.8 /s | 速度比例の抵抗係数 |
| `WHEELBASE` | 32 px | ホイールベース |
| `MAX_STEER_ANGLE` | 0.60 rad | 前輪の最大切れ角（約34°） |
| `A_LAT_MAX` | 900 px/s² | グリップ限界（最大向心加速度） |
| `GRIP_LOSS` | 0.98 | 滑り時の減速係数 |

### 4.6 導出値（制御設計の目安）

定数から導かれる、設計に役立つ数値です：

| 目安 | 値 | 導出 |
|------|-----|------|
| 最小旋回半径 | 約 47 px | `32 / tan(0.60)`（フルステア時） |
| フルステアで曲がりきれる限界速度（通常路面） | 約 205 px/s | `√(900 × 47)` |
| 同・アイス上（grip 0.42） | 約 133 px/s | `√(900 × 0.42 × 47)` |
| 通常路面の実質最高速度 | 約 325 px/s | 駆動と抵抗の釣り合い `260 / 0.8`（420 には抵抗のため届かない） |
| 制動距離（300 px/s → 0、ブレーキ全開） | 約 87 px | `v² / (2 × 520)`（抵抗の分さらに短くなる） |
| 旋回半径と速度の関係 | `v ≤ √(900 × grip × R)` | 半径 R で曲がるには速度をこれ以下に |

**含意**：前方レイの最大探知距離は 260 px（第6章）なので、壁を検知してからフルブレーキ
すれば約 325 px/s からでも止まれる計算ですが、判断が1フレーム遅れるごとに約 5 px 進みます。
「前方の壁までの距離に比例した目標速度」が有効な理由がここにあります。

## 5. 路面サーフェス

コース上の色つき領域は物理係数を倍率で変化させます。現在踏んでいる種別は `obs.surface` で分かります。

| surface | 見た目 | grip | accel | brake | drag | vmax | boost | 挙動の要約 |
|---------|--------|------|-------|-------|------|------|-------|------------|
| `road` | 通常 | 1.00 | 1.00 | 1.00 | 1.0 | 1.00 | 0 | 基準 |
| `ice` | 水色 | **0.42** | 0.80 | **0.50** | 0.35 | 1.00 | 0 | **滑る**。曲がれる限界速度が約65%に低下、ブレーキも半分しか効かない → 進入前に減速 |
| `mud` | 茶色 | 0.85 | **0.55** | 1.10 | **3.2** | 0.60 | 0 | **失速する**。抵抗が非常に大きく巡航速度は約56 px/s まで低下 → アクセル全開で押し切る |
| `boost` | 黄色 | 1.00 | 1.00 | 1.00 | 1.0 | **1.40** | **+360 px/s²** | **加速する**。上限588 px/s まで伸びる → 直後のコーナーで速度超過に注意 |

- 倍率の適用式は第4章を参照（例：アイス上のグリップ限界 = `900 × 0.42`）。
- 効果は**車の中心座標が領域内にある間だけ**適用されます。

## 6. センサー（レイキャスト）

車の中心から各方向へレイを飛ばし、**壁（走行不可領域）に当たるまでの距離 [px]** を返します。
`obs.rays` は次の5方向の dict です：

| キー | 車体前方を0とした角度 |
|------|----------------------|
| `'front'` | 0°（真正面） |
| `'front_left'` | −30° |
| `'front_right'` | +30° |
| `'left'` | −90°（真左） |
| `'right'` | +90°（真右） |

- 最大探知距離 **260 px**（それ以上開けていても 260 が返る）。
- 探索刻みは 4 px（距離の分解能）。
- **閉じている周回連動ゲート（第8.3節）も壁として検出される**。
  つまり「レイに映る＝物理的にも通れない」で一貫している。

典型的な使い方：

```python
obs.rays['front'] が小さい      → カーブ・行き止まりが近い → 減速
front_left − front_right の差   → 道が開いている方向 → その方向へ操舵（道なり走行）
left / right が小さい           → 壁に寄りすぎ → 反対側へ補正
```

## 7. 壁衝突

車の中心が走行不可領域に入ろうとしたフレームの挙動（実装：`engine/simulator.py`）：

1. 位置は更新されない（押し戻し）。ただし**向きの変化は反映される**
   （壁に正対して停止しても、ハンドルを切りながら加速すれば回頭して脱出できる）。
2. 速度が **30% に低下**する（`WALL_SPEED_FACTOR = 0.30`）。
3. 衝突カウント **+1**（タイムペナルティ **+2秒**）。
   壁に触れ続けている間は1回と数え、離れて再度当たると次の1回になる。

## 8. コースと進行

### 8.1 コースの構成要素

各コースは `courses/<name>/` の2ファイルで定義されます：

- `mask.png` … 白=走行可能 / 黒=壁 のビットマップ（コース形状そのもの）
- `meta.json` … チェックポイント座標列・スタート位置と向き・周回フラグ・特殊路面領域（zones）

### 8.2 チェックポイント（CP）と完走判定

| 項目 | 仕様 |
|------|------|
| 通過判定 | CP座標との距離が **45 px 未満**になったフレームで通過 |
| 通過順序 | 順番固定。`obs.next_cp` は常に「次に通るべき1個」を指す |
| 周回コース | CP0 = スタート地点。**3周**（CP数 × 3 個の関門を順に通過）で完走 |
| 非周回コース | 最後のCP = ゴール地点。1回到達で完走 |
| 制限時間 | **180 秒**。超えると走行打ち切り（DNF） |
| CPの数 | 各コース2〜5個程度と少ない。**CP間の直線上には必ず壁がある**（CPは目的地であって経路ではない） |

### 8.3 周回連動ゲート（本番コースの一部に登場）

- `meta.json` の zones に `type="gate"` として定義される**周回によって開閉する壁**。
- `(lap − 1) % period == open_phase` の周だけ通行可能（既定 period=2 ＝1周おきに交互）。
- 閉じている間は**物理（衝突）とセンサー（レイ）の両方で壁**として扱われる。
  → 「開いている道なりに走る」制御なら特別な対応は不要。
- 画面表示：赤=閉（壁）、緑の枠=開。

### 8.4 コース一覧

配布物に含まれるコースは **course_01** のみです。本番用のコースは当日順次配布されます。

| コース | 周回 | 難易度 | 特徴 |
|--------|------|--------|------|
| course_01 | 3周 | 初級 | スタジアム型（長い直線＋両端の半円）。固定幅。特殊路面（ice / mud / boost）が各1か所ずつある |

- 本番コースには、幅が不定の区間（広い/狭い）、**行き止まり**（目的地方向へ最短で突っ込むと
  袋小路に入る分かれ道）、周回連動ゲート（第8.3節）などの**追加の仕掛け**が登場することがあります。
  「目的地の方向へ向かうだけ」の制御はハマるため、レイで開いている道を選ぶ判断が必要です。

## 9. 走行結果の指標

走行終了時に結果出力へ表示される計測値です。どの指標を重視するか＝何を目標とするかの
設定は自由です：

| 指標 | 定義 |
|------|------|
| 衝突回数 `crashes` | 壁衝突イベントの回数 |
| 平均速度 `avg_v` | 全フレームの速度平均 |
| 滑らかさ `smooth` | ステア変化量の1フレーム平均（小さいほど滑らか） |
| 区間タイム `cp_times` | 各CP到達時刻（一部区間だけ遅くないか＝全体最適の分析用） |
| エラー回数 `errors` | `control()` の例外・不正返り値の回数 |

## 10. 制約事項

- **編集してよいのは `controllers/` 内のファイルだけ**。`engine/`・`render/`・`config.py`・
  `courses/` は変更禁止（変更しても本番環境では反映されない）。
- `sample_controller.py` は「改良前の基準」として**編集せず残す**（並走比較に使う）。
- `control()` 内の重い処理（大きなループ、ファイルI/O、外部通信など）は禁止。
  毎秒60回呼ばれるため、実時間の走行に直接影響する。
- 外部ライブラリの追加インストールは不可（標準ライブラリ＋既存環境のみ。`math` は自由に使える）。
